# Wusool Engine

Internal operating system for Wusool Capital advisors. Most tabs are a clickable prototype on a demo account with invented data; the Buyers and Sellers pages can read and write live Toolkit data.

- What to build: `docs/PRD.md`
- How it looks: `docs/DESIGN.md`
- Rules for contributors and Claude Code: `CLAUDE.md`
- Decisions: `docs/decisions/`

## Run

```bash
npm install
npm run dev
```

Checks before a pull request: `./checks.sh` (typecheck and build), then click through at 1440px and 390px wide.

## Deploy (Cloudflare)

Every merge to `dev` that touches `engine-frontend/` deploys to Cloudflare Workers through `.github/workflows/deploy-engine.yml` (decision 0007). Config: `wrangler.jsonc`. Address: `engine-dev.wusoolcapital.com`, behind Cloudflare Access (email one-time PIN, `@wusoolcapital.com` or `@dopaminecap.com`), managed in `infrastructure/terraform/stacks/engine-frontend`.

Local check of the production setup: `npm run build`, then `npx wrangler dev`.

## Demo or live data

`VITE_DATA=demo` (the default) runs every page on the invented data in `app/demo/`. `VITE_DATA=live` makes the Buyers and Sellers universes and the signed-in user come from the Toolkit; `deploy-engine.yml` builds `engine-dev` that way. Routes import everything from `app/api.ts`, which picks the demo or live function by name, so each live function keeps its demo twin's inputs and return shape.

The live client in `app/gen/` is generated by Kubb from `openapi.json`, which the Toolkit exports. After a Toolkit API change run `./checks.sh api` (or `cd ../server && uv run python scripts/export_openapi.py ../engine-frontend/openapi.json --app engine`, then `npm run gen:api`) and commit the result; CI fails on drift.

The edit and add drawers draw the Toolkit's extra Slack fields from the catalog it sends (`options.fields`) with `components/ui/detail-fields.tsx`; nothing there names a field, and the demo build has none.

`worker/index.ts` proxies `/api/v1/*` to the Toolkit in production. For local live mode run the Toolkit yourself and set `TOOLKIT_DEV_URL`; the Toolkit still needs a Cloudflare Access token, so live mode is meant for `engine-dev`.

## Working on the repo

- Branch from `dev`, one branch per tab, open a pull request into `dev`. The `Engine quality (required)` check runs typecheck and build.
- Run `./checks.sh` before a pull request, then click through at 1440px and 390px wide.

## Layout

- `app/root.tsx`: page shell (left nav, toast, phone notice)
- `app/api.ts`: the one module routes read and write through; re-exports the demo functions and swaps in the live ones when `VITE_DATA=live`
- `app/demo/`: invented data and `api.ts`, the demo functions
- `app/live/`: the Toolkit-backed functions, built on the generated client in `app/gen/` (do not edit)
- `worker/`: the Cloudflare Worker that serves the app and proxies `/api/v1/*`
- `app/routes/`: one file per built tab; `placeholder.tsx` for tabs not built yet
- `app/routes.ts`: route table, one entry per tab
- `app/lib/nav.ts`: the 13 tabs in 5 groups, used by the nav and the placeholders
- `app/components/shell/`: shell components
- `app/styles.css`: tokens and component styles from DESIGN.md
